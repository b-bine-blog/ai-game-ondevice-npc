# AI 게임 융합 기술 — 온디바이스 LLM NPC 멀티엔딩 게임

> 조선대학교 산학프로젝트1 (2026.03 ~ 2026.06, 15주) · 팀 고잉메리호 (4인)
> Unity 6 (6000.3.12f1) · C# · UndreamAI(LLMUnity) · Gemma-3-4B-it (Q4_K_M)

외부 서버 없이 PC 안에서 돌아가는 LLM NPC와 대화하는 **시스템 수리 어드벤처 게임**입니다.
대화와 퍼즐 결과로 쌓인 **호감도**가 맵 난이도(몹 수 · 이동속도 · 장애물)와 **4종 엔딩**을 결정합니다.

## 왜 만들었나

- **클라우드 AI NPC의 한계:** NVIDIA ACE, Ubisoft Neo NPC 등 AI NPC 시도는 대부분 클라우드 기반이라 서버 비용과 응답 지연 때문에 정식 출시작 적용이 드뭅니다.
- **고정 스크립트의 반복 피로:** 정해진 대사와 패턴은 다회차 플레이에서 쉽게 지루해집니다.

→ 서버 없이 로컬에서 LLM을 돌리고, 대화 결과가 게임 메카닉(맵 · 난이도 · 엔딩)에 직접 반영되도록 설계했습니다.

## 시스템 구조

```
플레이어 입력 → chatManager(채팅 UI)
            → 프롬프트 조립 (호감도별 말투 규칙 + 게임 상태별 상황 지시문)
            → LLMUnity · Gemma-3-4B Q4_K_M (로컬 추론)
            → NPC 응답 출력
            (호감도 증감은 모델이 아니라 코드가 키워드로 판별: 퍼즐 관련 첫 질문 +1)

퍼즐 결과(+1/+5/+4, 발판 실패 -1) · 전투(몹 3마리마다 -1)
            → 호감도(중앙 관리 변수)
            → 3지역 난이도(ApplyDifficulty) · 4지역 엔딩 분기
```

| 호감도 | 몹 수 | 이동속도 | 맵 상태 |
|---|---|---|---|
| -2 이하 (적대) | 전체 | 30 | 장애물 생성 · 1지역 추방 |
| -1 ~ 5 (일반) | 4 | 50 | 기본 경로 |
| 6 ~ 9 (우호) | 2 | 70 | 이동 가속 |
| 10 이상 (최상) | 0 | 50 | 경로 완전 개방 |

## 기술 선택 이유

| 선택 | 이유 | 감수한 점 |
|---|---|---|
| 온디바이스 LLM (Gemma-3-4B, Q4_K_M) | 서버 비용 0원 · 오프라인 실행 · 대화가 기기 밖으로 나가지 않음 | 대형 모델보다 답변 품질이 낮고, 저사양 PC에서 응답 약 1분 |
| UndreamAI LLMUnity | Unity 안에서 GGUF 모델을 바로 구동, 별도 서버 프로세스 불필요 | 패키지 의존 (모델 선정 · 연동 구현은 팀원 담당) |
| 판단은 코드, 표현은 LLM | 소형 모델은 상황 판단이 흔들림 → 퍼즐 상태 · 호감도 판정은 코드가 하고 모델에는 말투 · 상황 지시만 전달 | 상황별 지시문을 코드로 계속 관리해야 함 |

## 트러블슈팅: 프롬프트를 고칠수록 불안정해지던 NPC

- **현상:** 2지역 테스트에서 NPC가 같은 문장을 반복하고, 긍정적인 대화를 적대적으로 오판해 호감도를 깎음
- **1차 시도:** 시스템 프롬프트 수정, Temperature · Repeat Penalty 등 파라미터 조정 → 답변이 느려지고 오히려 불안정
- **2차 해결:** 판단을 모델에서 코드로 옮김. 퍼즐 클리어 여부 · 실패 문의 여부를 코드가 먼저 판별하고, 상황별 지시문과 호감도별 말투 · 문장 수 제한만 프롬프트에 주입 → 응답이 안정되어 최종 빌드까지 유지

## 폴더 구조

Unity 프로젝트 전체가 아니라 **팀이 직접 작성한 C# 스크립트(28개)만** 올렸습니다.
LLMUnity · TextMeshPro 등 패키지와 예제 코드, 에셋, 모델 파일은 제외했습니다.

```
Scripts/
├─ AI_NPC/     ChatManager            NPC 프롬프트 조립 · LLM 호출 · 키워드 기반 호감도
├─ Puzzle/     PuzzleManager          발판 퍼즐 (정답 1 → 3 → 2)
│              BinaryQuizManager      이진수 퍼즐
│              EnemyZoneTrigger       몹 유도 숨은 퍼즐
├─ GameFlow/   DifficultyManager      호감도별 동적 난이도 (몹 수 · 이동속도 · 장애물)
│              EnemyDeathManager      2지역 통로 개방 조건
│              GameManager_1AREA      1지역 글리치 목표 (추방 시 3 → 5개)
│              EndingManager          호감도별 4종 엔딩 분기
│              EndingTriggerRelay · TutorialManager · SceneFadeIn
├─ Portal/     Portal · Portal3 · SceneTeleporter · ToEndingPortal · ToMainFinal
├─ Player/     PlayerController · PlayerHealth · PlayerShooting · JoystickController
├─ Enemy/      EnemyHealth · DroneEnemyAI · MeleeEnemyAI
├─ UI/         MainMenu · GameMenu · IntroManager · MinimapToggle
└─ _Prototype/ NPCDialogue            LLM 도입 전 고정 대사 시안 (최종 빌드 미사용)
```

> 원본 파일의 한글 주석 일부가 인코딩(EUC-KR) 문제로 깨져 있어 의미에 맞게 복원했고, 핵심 로직에 설명 주석을 추가했습니다. 코드 동작은 바꾸지 않았습니다.

## 실행 방법

1. 이 저장소는 핵심 스크립트 모음입니다. 실행하려면 원본 Unity 프로젝트(Unity 6, 6000.3.12f1)가 필요합니다.
2. LLM 모델 파일(`gemma-3-4b-it-Q4_K_M.gguf`, 약 2.5GB)은 GitHub 용량 제한으로 저장소에 포함하지 않았습니다. Hugging Face에서 받아 LLMUnity의 LLM 컴포넌트에 연결합니다.
3. 첫 씬(타이틀)에서 실행합니다.
